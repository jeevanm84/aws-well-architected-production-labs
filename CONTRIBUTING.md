# Contributing

Contributions should improve architecture reasoning, measurable evidence, failure analysis, or reusable learning value.

1. Fork the repository and create a focused branch.
2. Start with workload requirements rather than a preferred AWS service.
3. Include all six pillars, decisions, trade-offs, failure modes and verification.
4. Keep examples account-free and original.
5. Run `./scripts/check.sh` and open a pull request.

Never include credentials, account IDs, employer/customer data, internal URLs, production logs, billing exports, or proprietary architecture.
